# PRD 生成 (Generate PRD) Skill

本 Skill 将用户的碎片化需求或单一功能点，转化为具备专业规范、边界清晰、可落地的产品需求文档（PRD），覆盖背景目标、用户场景、流程、功能细节、埋点与非功能需求等核心模块，并额外生成**页面交互流程图**，帮助开发理解页面跳转逻辑。

## 任务步骤

### 1. 确认核心信息
与用户（或业务输入方）依次核实以下内容，若用户未明确，则根据功能点合理推断并注明待确认项：

- **项目背景**：当前存在什么问题？为什么在这个时间点做？预期的业务价值是什么？
- **目标用户**：功能涉及哪些用户角色？各自的权限层级（如普通用户、管理员、审核员）？
- **核心场景**：用户在什么情况下使用该功能？典型业务流程是怎样的？典型的业务痛点及流程闭环说明
- **页面跳转关系**（可选）：用户可描述页面之间的跳转路径（如“首页 → 课程列表 → 课程详情 → 报名表单”），若未提供则根据功能点推断。
- **量化目标**（可选）：如果可能，明确可衡量的指标（如转化率提升 X%，操作时长降低 Y 分钟）。

### 2. 按模板输出标准 PRD 结构
基于确认的信息，严格按以下模块输出，确保逻辑完整、细节可落地：

#### 2.1 文档修订记录
以表格形式记录版本、日期、作者、修改内容。

#### 2.2 项目背景与目标
- **背景**：现状与痛点（可附带数据）
- **目标**：定性描述 + 定量指标（KPI/OKR 挂钩）

#### 2.3 用户角色与场景
- **角色定义**：角色名称、职责、系统权限（表格形式）
- **用户故事**：按“作为[角色]，我想[执行动作]，以便于[达到目的]”格式列出

#### 2.4 业务流程图
使用 Mermaid 语法绘制，涵盖主流程、分支流程、逆向流程。

#### 2.5 页面交互流程图（Page Flow）
- **目标**：展示用户在不同页面之间的跳转路径，便于开发理解界面流转。本流程图将直接嵌入 PRD 文档，无需外部链接。
- **生成方式**（根据可用素材自动选择）：
  - **若用户提供了页面截图（或已存在 `docs/images/prototype/` 下的截图）**：
    1. 收集所有相关页面的截图（路径由用户提供或自动扫描）。
    2. 使用 Python Pillow 库将截图按流程顺序拼接成一张长图（横向或纵向），并在截图上绘制箭头和跳转说明文字。
    3. 将合成图保存为 `docs/images/page_flow_[功能名称]_[日期].png`。
    4. 在 PRD 中通过 `![页面交互流程图](相对路径)` 直接嵌入该图。
  - **若没有截图**：
    1. 生成 Mermaid 流程图代码块，节点为页面名称，箭头标注触发动作（如“点击‘咨询’按钮”）。
    2. 将 Mermaid 代码直接写入 PRD 的该章节，支持在支持 Mermaid 的 Markdown 渲染器中自动显示。
- **内容要求**：
  - 列出所有涉及的核心页面（如首页、列表页、详情页、表单页、结果页）。
  - 标注每个页面的主要入口（如底部导航、按钮点击）。
  - 如有分支条件（如根据用户身份跳转不同页面），需在流程图中体现。
  - 需要在图上用红色框圈选出点击的区域
- **与业务流程图的关系**：业务流程图侧重逻辑与数据流转，页面流程图侧重界面层跳转，两者互补。

#### 2.6 功能需求详情
- **前端交互**：页面元素、操作路径、反馈提示（成功/失败/加载等）
- **后台逻辑**：数据流转、规则引擎、状态机（状态定义与流转条件）
- **异常处理**：网络异常、空数据、并发冲突、权限不足、第三方服务失败等场景下的系统行为

#### 2.7 非功能性需求
- **性能**：响应时间、并发量、数据加载策略
- **安全性**：权限校验、敏感数据脱敏、操作日志
- **合规**：若涉及个人信息，需注明隐私保护要求

#### 2.8 数据埋点需求
以表格形式列出埋点事件，包括：事件名称、触发时机、上报参数、用途（与量化目标关联）。

#### 2.9 附录/术语表（必要时）
统一说明文档中出现的业务术语、缩写、关联系统接口等。

### 3. 输出格式与存储
- 将上述 PRD 以 **Markdown** 格式输出，层级清晰，表格、代码块规范使用。
- 若用户明确项目目录，可将内容保存为 `docs/PRD_[功能名称]_[日期].md`；否则仅输出内容，提示用户可自行保存。
- 如果生成了独立的 HTML 流程图文件，同时输出该文件路径，并在 PRD 中添加引用链接。

### 4. 页面交互流程图图片生成的技术细节（当有截图时）
- **依赖**：自动安装 `Pillow`（若不存在）。
- **步骤**：
  1. 统一所有截图宽度（如 400px），按比例缩放高度。
  2. 根据跳转关系确定截图顺序（如从左到右或从上到下）。
  3. 创建空白画布，宽度为单张宽度，高度为所有截图高度之和 + 箭头区域预留空间。
  4. 依次粘贴截图，并在相邻截图之间绘制箭头（使用 `ImageDraw.line` 和 `polygon` 绘制箭头三角形）。
  5. 可选：在箭头上方添加文字标签（如“点击‘咨询’按钮”），使用 `ImageDraw.text`。
  6. 保存为 PNG。

## 注意事项
- **避免模糊词**：不使用“尽量”“友好”“合理”等主观表述，改为具体条件（如“3 秒内响应”“文案为‘暂无数据’”）。
- **优先级标记**：功能点需标注优先级（P0/P1/P2/P3），便于研发排期。
- **边界优先**：异常流程与主流程同样重要，缺失时需主动向用户提问或根据常识补充。
- **领域适配**：若用户提及特定领域（如教育、医疗、电商），在用户角色、业务规则、术语上做针对性细化。
- **页面流程图质量**：若使用截图拼接，确保箭头指向清晰，必要时可生成多个子图；若使用 Mermaid，确保节点命名易懂。

## 示例触发语句
用户输入：
> “我要做一个教育招生工具的‘小表单直接引导加微功能’功能，帮我写一份 PRD，并生成页面交互流程图。这里有三个截图：首页.png、表单页.png、加微页.png，跳转关系：首页点击‘咨询’→表单页，表单页提交后→加微页。”

Skill 将按上述步骤生成完整的 PRD，并将三个截图拼接成一张带箭头的页面交互流程图图片，嵌入 PRD 文档中，最终输出 `docs/PRD_小表单引导加微_2026-04-01.md` 和对应图片文件。
