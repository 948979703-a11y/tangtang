# 产品原型 (Prototype Builder) Skill

本 Skill 旨在快速将产品思路实现为可直观交互的 React 前端原型，采用 Tailwind CSS 进行样式开发，用于验证想法、汇报演示以及对齐研发预期。同时引入**版本管理**机制，方便追踪原型演进过程，支持多版本并存与切换。

## 任务步骤

1. **确认页面类型、主要模块及版本规划**
   - 与业务侧/用户确认当前页面所需适配的终端要求（例如：移动端 H5 页面、PC Web 页面、B端后台管理布局等）。
   - 罗列并搜集页面内必须包含的核心骨架与业务组件（如导航栏、操作按钮、数据表格展示、弹窗）。
   - **明确版本信息**：询问是否需要生成多个版本，或指定当前版本号（如 `v1.0`、`v2.0`）。若需迭代，记录本次原型属于第几版，并了解前一版的主要改动点。

2. **生成基于 React + Tailwind CSS 的原型代码**
   - **技术栈选择**：使用 React（函数组件 + Hooks）构建 UI，利用 Tailwind CSS 实现样式，确保响应式与现代化设计。
   - **产出形式**（二选一，优先选择单文件方式以方便预览）：
     - **单文件 HTML**：生成一个独立的 HTML 文件，通过 CDN 引入 React、ReactDOM、Tailwind CSS，并将 React 组件代码内嵌，可直接在浏览器中运行。
     - **组件代码 + 说明**：若用户期望拆分文件，可提供核心组件代码（如 `App.jsx`）及简要的运行指引（如 `npx create-vite` + 安装 Tailwind 的步骤），但需确保用户能快速上手。
   - **核心交互**：使用 React 状态管理（`useState`、`useEffect` 等）实现点击、选项卡切换、模拟数据加载、表单提交等基础交互。
   - **版本管理实现**：
     - 在生成的代码中，通过常量或注释明确标注版本号（如 `const APP_VERSION = 'v1.0';`）。
     - 若需要多版本并存，可采用以下任一方式：
       - 将不同版本分别输出为独立的文件（如 `prototype_v1.html`、`prototype_v2.html`），并在文件名中体现版本。
       - 在单文件内提供版本切换控件（如下拉菜单），利用 React 动态渲染不同版本的组件或内容，实现版本对比。
     - 在代码注释或额外生成的 `CHANGELOG.md` 中记录版本变更历史，便于追溯。

3. **提供预览方式与版本管理说明**
   - 如果采用单文件 HTML，确保代码可直接保存为 `.html` 文件并在现代浏览器中打开运行。
   - 如果采用组件代码形式，提供清晰的运行步骤（如安装依赖、启动开发服务器）。
   - **额外输出**：如果生成多版本，提供简要的版本说明文档，描述各版本之间的差异及切换方法；若使用版本切换控件，在页面上添加提示文案，指导用户如何查看不同版本。

4. 自动截图（利用浏览器 Agent）
- **启动页面**：
  - 对于单文件 HTML，直接打开本地文件。
  - 对于组件代码，尝试启动开发服务器（如 `npm run dev`）并等待就绪。
- **截图范围**：
  - 根据用户指定或从页面结构中识别关键页面（如首页、列表页、表单页、弹窗状态）。
  - 每个页面至少截取一张图，保存至 `docs/images/prototype/`，命名格式：`[页面名]_v[版本号].png`。
- **截图反馈**：输出截图路径列表。


## 版本管理最佳实践

- **版本命名**：遵循语义化版本（如 `v1.0.0`）或项目自定义规则，确保可读性。
- **版本历史**：每次生成新版本时，对比旧版本，在 `CHANGELOG.md` 中记录新增功能、修复问题、样式调整等。
- **分支场景**：若用户提出多个方向的原型（如 A/B 测试），可将不同方向视为不同版本并行生成，便于后续决策。
- **清理旧版本**：当版本迭代过多时，主动提示用户是否需要归档或删除旧版本，保持工作区整洁。
