# 需求分析 (Analyze Requirements) Skill

本 Skill 将用户的碎片化想法或一句话需求，转化为结构化的需求分析报告，明确核心目标、用户角色、场景和关键功能点，并识别需要进一步澄清的问题。

## 任务步骤

1. **接收原始需求**
   获取用户提供的需求描述（文字、图片、语音转文字等）。

2. **需求拆解与提问**
   依次分析和澄清以下维度，若用户未明确则列出待确认问题：
   - **项目背景**：当前存在什么痛点？为什么现在要做？预期带来什么价值？
   - **目标用户**：谁将使用该功能？是否有多个角色？权限有何差异？
   - **核心场景**：用户在什么情况下会触发该功能？完整的业务路径是什么？
   - **量化目标**（可选）：是否有可衡量的指标（转化率、时长、满意度等）？

3. **输出结构化需求分析报告**
   按以下格式输出 Markdown：
   - **需求概述**：一句话总结
   - **背景与痛点**
   - **目标用户与角色**（含权限描述）
   - **核心场景**（用户故事格式）
   - **功能点列表**（含优先级建议）
   - **待澄清问题**（如有时）

4. **与用户确认**
   若存在待澄清问题，暂停并提示用户回答。全部明确后，可提示用户继续使用 `generate-prd` 生成正式文档。

## 注意事项
- 保持中立，不预设技术方案，聚焦业务和用户。
- 如果用户提供了截图或竞品参考，可主动分析其设计模式并融入报告。
- 功能点列表应区分 P0/P1/P2，便于后续排期。
