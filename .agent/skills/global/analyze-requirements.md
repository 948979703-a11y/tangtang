# 需求分析 (Analyze Requirements) Skill

本 Skill 将用户的碎片化想法或一句话需求，结合**新东方 K12 招生平台**（引流与蓄养）的业务上下文，转化为结构化的需求分析报告。目标是用最短时间厘清核心目标、用户角色、场景和关键功能点，并提前识别需要进一步澄清的问题，避免 PRD 阶段返工。  
**标准流程固定为：需求分析 -> 原型交互 -> PRD；需求分析完成后不得直接产出 PRD。**

---

## 业务上下文速查（每次分析前必读）

> 分析需求时，需将用户碎片想法与以下业务背景自动关联，避免需求漂移、与现有系统重复建设或脱离当前技术生态。

### 所属平台与项目矩阵

本仓库承载新东方 K12 **引流 + 蓄养**产品矩阵，涵盖以下 5 个核心子项目：

| 项目 | 目录 | 定位 |
| --- | --- | --- |
| 小表单 | `mini-form` | 线下地推引流，低摩擦收集线索 |
| 打卡 | `check-in` | 社群蓄养，提升每日黏性 |
| 体验课 | `trial-class` | O2O 转化漏斗，锁定高意向用户 |
| 老带新 | `referral` | 老用户裂变拉新 |
| 客户跟进 | `customer-follow-up` | 企微侧边栏，全息画像辅助转化 |

### 核心角色速查

| 角色 | 常见称呼 | 核心职责 | 常用工具 / 模块 |
| --- | --- | --- | --- |
| 市场老师 | 市场、地推老师 | 策划并执行市场活动，线下地推收集线索 | 小表单 |
| 社群老师 | 社群、运营老师 | 运营私域社群，蓄养意向用户，提升活跃度 | 体验课、小课堂、打卡 |
| 顾问老师 | CC、课程顾问 | 跟进线索、推进转化，促成用户付费报名 | 体验课、客户跟进、SCRM 系统 |
| 店长 | 校区店长 | 管理校区日常运营，负责前台接待用户 | 后台管理、数据大盘 |
| 授课老师 | 任课老师 | 为已报名学员提供课程教学 | 课程系统（非本平台核心场景） |
| 学员 / 家长 | C 端用户 | 填单、打卡、报名、观看小课堂 | 小程序 / H5 |

### 技术与设计规范约束

- **前端**：React + Tailwind CSS，移动端优先（`app-container` 布局）
- **原型托管**：`https://tangtang-prototype.netlify.app/`
- **UI 主色系**：teal / indigo；卡片：白底 + 细边框 + 圆角
- **交互规范**：可点击区域提供 hover/active 反馈；空状态使用简洁文案；弹窗/抽屉复用已有样式
- **数据关键字段**：`studentcode`（学员唯一 ID）是多个模块集成的核心枢纽

## 分析步骤

### 第 1 步：读取用户输入

接收用户描述的需求（文字、截图、竞品链接、语音转文字均可）。**不做任何臆断**，先完整消化再开始分析。

若用户提供了截图或竞品参考，**主动分析其设计模式**并在报告中标注设计借鉴点。

---

### 第 2 步：锁定归属项目与核心问题

在开始拆解之前，先明确以下 3 个关键判断：

1. **归属项目**：本次需求属于上表中哪个子项目（或新建项目）？
2. **端口归属**：是 B 端功能（老师/主管操作后台）、C 端功能（学员/家长小程序/H5），还是 B+C 联动？
3. **需求类型**：是全新功能（新增）、对现有功能的迭代（优化/扩展），还是数据集成（接入第三方或跨模块聚合）？

---

### 第 3 步：多维度拆解

逐一分析以下维度，**缺什么问什么**，不预设答案：

#### 3.1 业务背景与痛点
- 当前存在什么问题？用户/老师当前是怎么处理这个场景的？
- 为什么现在做？是否有外部触发（政策、竞品、数据下滑）？
- 不做这件事的代价是什么？

#### 3.2 目标用户与角色
- 谁在用这个功能？对应"角色速查"表中的哪个角色？
- 是否涉及多个角色？角色之间有无权限差异、数据隔离需求？
- 是否有特殊场景人群（如新入职老师 vs 有经验老师）？

#### 3.3 核心场景（用户旅程）
- 用户在什么时候、什么入口触发该功能？
- 完整的业务路径是什么（从触发到结果）？
- 有无例外流程（如数据为空、权限不足、网络失败）？

#### 3.4 量化目标（可选但强烈建议）
- 是否有可衡量的目标？（如：老师跟进效率提升 X%、C 端留资率提升 Y%）
- 对应哪个业务指标：CPL / 社群留存率 / 体验课到课率 / 最终转化率？

#### 3.5 与现有模块的关系
- 本需求是否需要复用现有组件或数据？（如是否依赖 `studentcode`？）
- 是否与其他子项目有联动？（如打卡完成后更新客户跟进的画像信息）
- 是否存在与已有功能重复建设的风险？

---

### 第 4 步：深入提问与确认（⚠️ 必须等用户回复后才能继续）

基于第 3 步的拆解，整理出本次需求中**尚未明确或存在歧义**的关键问题，以清单形式向用户提问。

**提问原则：**
- 单次问题不超过 6 个，按重要程度排序，优先问影响功能边界的核心问题。
- 每个问题须带上**提问意图**（括号内简述），帮助用户理解为什么要问。
- 如果某个维度信息已足够清晰，不要为了提问而提问。
- 问题应聚焦：功能边界、角色权限、数据依赖、例外处理、与现有模块的关系。

**提问输出格式：**

```
在正式输出需求分析报告之前，我有几个关键问题需要你确认：

1. **[问题]**（意图：明确功能边界，避免过度建设）
2. **[问题]**（意图：确认角色权限，防止数据越权）
3. **[问题]**（意图：确定数据来源，评估接入复杂度）
...

请回答以上问题后，我将输出完整的需求分析报告。
```

⚠️ **本步骤结束后必须停止输出，等待用户回复。收到回复后，将答案补充进分析结论，再执行第 5 步。**

---

### 第 5 步：输出结构化需求分析报告（用户确认后执行）

按以下 Markdown 格式输出，**内容必须具体，不允许出现"合理""友好""尽量"等模糊表达**：

```markdown
# 需求分析报告：[需求名称]

## 1. 需求概述
> 一句话总结：[角色] 在 [场景] 下需要 [做什么]，以实现 [业务价值]。

## 2. 归属信息
- **子项目**：[小表单 / 打卡 / 体验课 / 老带新 / 客户跟进 / 新项目]
- **端口**：[B 端 / C 端 / B+C 联动]
- **需求类型**：[新增 / 优化 / 数据集成]

## 3. 业务背景与痛点
[描述当前痛点，尽量用具体场景或数字量化]

## 4. 目标用户与角色

| 角色 | 职责 | 权限范围 |
| --- | --- | --- |
| [角色1] | ... | ... |

**用户故事：**
- 作为**[角色]**，我想**[执行动作]**，以便于**[达到目的]**。

## 5. 核心场景与业务路径
[描述触发入口 → 操作步骤 → 结果反馈的完整路径，可使用简单流程文字描述]

**例外场景：**
- 数据为空时：[描述]
- 权限不足时：[描述]
- 接口异常时：[描述]

## 6. 功能点列表

| 优先级 | 功能点 | 说明 |
| --- | --- | --- |
| P0 | [必须做] | [解决核心痛点] |
| P1 | [应该做] | [提升体验] |
| P2 | [可以做] | [锦上添花] |

## 7. 与现有模块的关系
- **依赖字段**：[如 studentcode]
- **复用组件**：[如分层测卡片组件]
- **联动模块**：[如打卡完成 → 更新客户画像]

## 8. 量化目标（若有）
- 目标指标：[具体指标名称]
- 预期收益：[数字或方向]
```

---

### 第 6 步：确认与推进

- 报告输出完毕后，主动提示用户：
  > "需求分析已完成，下一步进入原型交互确认。是否继续使用 `prototype-builder` skill 生成页面交互原型？（PRD 需在原型确认后再输出）"

- 若用户要求“直接生成 PRD”，需先明确回复：
  > "当前流程要求先完成原型交互确认，再进入 PRD 编写。我先为你生成原型方案。"

---

## 注意事项

- **不预设技术方案**：分析阶段聚焦业务和用户，不讨论"用 Redux 还是 Context"这种技术决策。
- **强调边界场景**：数据为空、权限不足、接口失败，这三类异常在新东方内部系统中高频出现，必须提前识别。
- **功能优先级务必标注**：P0 = 上线必须有 / P1 = 本期目标 / P2 = 后续排期，与研发沟通成本直接相关。
- **结合原型现状**：若对应子项目已有原型页面（`https://tangtang-prototype.netlify.app/`），分析时注明该功能是现有页面迭代还是新增页面。
- **截图/竞品参考**：若用户提供了图片，需提取设计模式并在"功能点列表"中注明借鉴点。

## 示例触发语句

**用户输入：**
> "我想在客户跟进里加一个标签功能，让老师可以给学员打自定义标签，比如'高意向''需回访'这种。"

**Skill 分析流程：**

**第 1-3 步（内部拆解）：**
- 归属 → `customer-follow-up` 项目，B 端功能，需求类型：新增
- 角色 → 推广老师（打标签），业务主管（可能需要看标签统计）
- 场景 → 企微侧边栏查看学员信息时，通过标签快速分类管理线索池

**第 4 步（向用户提问，停止等待回复）：**
```
在正式输出需求分析报告之前，我有几个关键问题需要你确认：

1. **标签是仅自己可见，还是整个团队共享？**（意图：决定数据存储是按用户维度还是按团队维度）
2. **是否有标签数量上限？**（意图：影响 UI 展示策略和后端设计）
3. **是否需要按标签筛选学员列表？**（意图：决定本期是否需要做标签检索功能，影响工作量）
4. **标签是固定预设还是完全自定义？**（意图：预设标签可减少开发量，但自定义更灵活）

请回答以上问题后，我将输出完整的需求分析报告。
```

**第 5 步（用户回复后输出完整报告）：**
根据用户回答补充结论，输出标准格式的需求分析报告。
