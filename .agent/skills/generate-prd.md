# PRD 生成 (Generate PRD) Skill

本 Skill 会引导你将业务碎片化想法或者单一用户诉求，转化为具有高度专业规范且供研发审阅可落地的产品需求文档 (PRD)。

## 任务步骤

1. **确认核心信息**
   与用户或者业务输入方依次核实：
   - **项目背景**：解决什么问题，为什么这个时候要做？
   - **目标用户**：该功能模块具体使用者是谁？权限如何？
   - **核心场景**：典型的业务痛点及流程闭环说明。

2. **按模板输出标准 PRD 结构**
   输出必须基于以下模块结构并保持层级条理：
   - **项目背景与目标**：定性痛点阐述与定量指标目标（KPI/OKR挂钩等）。
   - **用户故事 (User Story)**：使用规范格式撰写（“作为[某角色]，我想[执行动作]，以便于[达到目的]”）。
   - **功能列表**：拆解细分功能，并根据资源为每个特性标定明确的需求优先级（P0/P1/P2/P3）。
   - **业务流程**：详述业务交互流转链路、主分支状态机及其包含的逆向流程。
   - **数据埋点需求**：详细列出为了追踪目标而需沉淀和上报的曝光、点击或时长类相关埋点指标。
   - **非功能需求**：系统安全与兜底降级方案、合规与性能（延迟、并发、扩展性）规范要求。

3. **输出为 Markdown 并保存到 docs/ 目录**
   - 将这套 PRD 转化为标准的 Markdown 语法以便跨平台展示。
   - 生成后将该文件自动化存储至项目的 `docs/` 目录下。
